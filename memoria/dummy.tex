\chapter{Antecedentes y justificación}

Vivimos en un país en el que los deportes por excelencia siempre han sido el fútbol y el baloncesto, aunque también hay muchos más deportes con gran visibilidad en España. No obstante, también existen cantidad de deportes minoritarios en nuestro país. Estos deportes carecen de profesionalización debido a la escasa visibilidad que se les proporciona. Por ello, estos clubes disponen de recursos mucho más limitados que los de los clubes deportivos profesionales.

El hockey línea en España es un deporte minoritario y semiprofesional, que en los últimos años ha ganado mucha visibilidad gracias a la retransmisión en directo de sus partidos en plataformas de \textit{streaming} como YouTube o Twitch. Lamentablemente, esto no es suficiente para profesionalizar este deporte.

El club deportivo tomado como referencia gestiona los procesos de sus distintos equipos acorde a su profesionalidad. Esto implica que dichos procesos (convocatorias, avisos, pedidos de material, análisis de partidos, etc.) se lleven a cabo a través del grupo de Whatsapp del equipo, de la intranet del club o de otra herramienta. Esto hace que sea necesario disponer de varias aplicaciones distintas, haciendo que la gestión de los equipos sea un proceso engorroso y tedioso.

Este proyecto surge de la idea de proporcionar una solución web que centralice esos procesos del club deportivo semiprofesional.

\chapter{Objetivos y alcance}

\section{Objetivos}

El objetivo principal de este proyecto es diseñar y desarrollar una solución web que organizace y facilite los procesos de gestión de un equipo deportivo, a la vez que proporciona herramientas para mejorar su rendimiento. Cabe destacar que este proyecto ha sido diseñado para uno de los equipos de un club en específico. Para lograr el objetivo principal del proyecto, se han establecido varios objetivos basándose en el principal. Estos objetivos servirán para comprobar si el resultado final del proyecto es un éxito o un fracaso. Dichos objetivos son los siguientes:

\begin{itemize}
  \item Objetivo 1: Diseñar y desarrollar una aplicación web que centralice los procesos de gestión más importantes y repetitivos del equipo deportivo.
  \item Objetivo 2: Implementar un sistema de login que permita el acceso únicamente a integrantes del club.
  \item Objetivo 3: Implementar un sistema de seguimiento de incidencias y estadísticas de los partidos en directo.
  \item Objetivo 4: Desarrollar un módulo inteligente que ofrezca recomendaciones sobre aspectos del partido a mejorar.
  \item Objetivo 5: Implementar distintos tipos de roles para el acceso a la aplicación web.
  \item Objetivo 6: Diseñar una interfaz original y personalizada para el club deportivo de referencia.
  \item Objetivo 7: Desarrollar una aplicación web adaptable a cualquier tipo de pantalla y dispositivo.
\end{itemize}

\section{Alcance}

Dado el carácter académico de este trabajo, el proyecto ha sido desarrollado con recursos y tiempo limitados. Esto implica que su alcance ha tenido que determinarse con claridad desde el principio. Además, se planea la ampliación del proyecto una vez realizada su defensa, por lo que delimitar sus funcionalidades para la presentación en la universidad ha sido una parte importante. Los objetivos anteriormente mencionados forman parte del alcance. Además se enumeran a continuación aspectos que también entran en el mismo:

\begin{enumerate}
  \item Desarrollo de la base de datos.
  \item Implementación de un sistema de login social.
  \item Desarrollo de la API REST.
  \item Implementación de un modelo de inteligencia artificial generativa comercial.
  \item Uso de Docker para el despliegue de la solución.
\end{enumerate}

Para la realización de este proyecto, también ha sido fundamental tener claro qué no forma parte del alcance de éste:

\begin{enumerate}
  \item Desarrollo de un sistema de seguimiento de jugadores y disco en tiempo real.
  \item Implementación de diferentes equipos del club.
  \item Desarrollo y entrenamiento de un modelo de inteligencia artificial propio.
  \item Almacenamiento de datos por temporadas.
  \item Persistencia de incidencias de partidos.
\end{enumerate}

\section{Especificación del diseño}

Para llevar a cabo el proyecto, ha sido necesario especificar el diseño del mismo antes de empezar con su desarrollo. Dicho diseño ha sido especificado en base a los requisitos funcionales y no funcionales y los objetivos del proyecto. El propósito de este apartado es definir el diseño de la arquitectura de la solución, el diseño relacional de la base de datos y el diseño de la interfaz de la aplicación web.

\begin{enumerate}
  \item \textbf{Backend:} Está desarrollado en Java 21, haciendo uso del framework SpringBoot. La parte backend se encarga de comunicarse con la base de datos mediante una API REST, desarrollada con las herramientas que proporciona SpringBoot para ello. Almacena datos y los recupera cuando es necesario, y los envía a la parte frontend para que se ella la que se encargue de mostrar la información al usuario.
  \item \textbf{Frontend:} El frontend es quien se encarga de recibir los datos que llegan de la parte backend para mostrarlos al usuario en pantalla. Está desarrollado en con React.
  \item \textbf{Base de datos relacional:} El backend se comunica con ella para almacenar y recuperar los datos que sean necesarios cuando sea necesario. Funciona como almacenamiento persistente del proyecto, y se ha hecho uso de MySQL para su gestión.
  \item \textbf{Anthropic:} Es una organización que dispone de modelos de inteligencia artificial generativa. La parte frontend llama a la API REST del proyecto para que sea el backend quien se comunique con uno de los modelos de IA de Anthropic. El backend recibirá la respuesta del modelo y la enviará al frontend para mostrarla al usuario.
  \item \textbf{Docker:} Es una herramienta de contenerización que permite empaquetar una aplicación y sus dependencias en un contenedor. Se utilizará para empaquetar la aplicación en un contenedor y poder ejecutarla en cualquier entorno.
\end{enumerate}

\subsection{Diseño de la arquitectura de la solución}

La solución está basada en una arquitectura cliente-servidor, compuesta por una parte backend que ejecuta toda la lógica de negocio y una parte frontend que muestra al usuario la información. La parte backend hace uso de una base de datos relacional para almacenar toda la información del proyecto. Además, el backend se comunicará con Anthropic para utilizar uno de sus modelos de IA. El proyecto estará embebido dentro de un contenedor de Docker.

\section{Tecnologías y herramientas utilizadas}

\subsection{Maven}

Maven es una herramienta de gestión de proyectos de proyectos software. Se ha utilizado en este proyecto para automatizar la compilación y construcción de la parte servidora del proyecto. Además ha ayudado ha gestionar las dependencias del proyecto, asegurando las distintas dependencias necesarias para que la parte backend del proyecto funcione correctamente.

\subsection{Spring Boot}

Spring Boot es un framework basado en el framework Spring que facilita el desarrollo de aplicaciones web. En este proyecto se ha utilizado para desarrollar la parte servidora de la aplicación web, encargada de gestionar las distintas funcionalidades que ofrece la aplicación.

\subsection{React}

React es una biblioteca de JavaScript diseñada para el desarrollo de interfaces web. En este proyecto se ha utilizado para desarrollar la parte cliente de la solución, que se encarga de mostrar los datos proporcionados por la parte servidora de una forma visual y agradable para el usuario.

\subsection{MySQL}

MySQL es un sistema de gestión de bases de datos relacionales de código abierto. Se ha utilizado en este proyecto para gestionar los datos de los que hace uso la solución web.

\subsection{Docker}

Docker es una plataforma de contenedores que permite empaquetar una aplicación en un contenedor junto con todas sus dependencias. Se ha utilizado para crear contenedores con cada uno de los servicios del proyecto y orquestar su ejecución con Docker Compose.
