\chapter{Antecedentes y justificación}

Vivimos en un país en el que los deportes por excelencia siempre han sido el fútbol y el baloncesto, aunque también hay muchos más deportes con gran visibilidad en España. No obstante, también existen cantidad de deportes minoritarios en nuestro país. Estos deportes carecen de profesionalización debido a la escasa visibilidad que se les proporciona. Por ello, estos clubes disponen de recursos mucho más limitados que los de los clubes deportivos profesionales.

El hockey línea en España es un deporte minoritario y semiprofesional, que en los últimos años ha ganado mucha visibilidad gracias a la retransmisión en directo de sus partidos en plataformas de \textit{streaming} como YouTube o Twitch. Lamentablemente, esto no es suficiente para profesionalizar este deporte.

El club deportivo tomado como referencia gestiona los procesos de sus distintos equipos acorde a su profesionalidad. Esto implica que dichos procesos (convocatorias, avisos, pedidos de material, análisis de partidos, etc.) se lleven a cabo a través del grupo de Whatsapp del equipo, de la intranet del club o de otra herramienta. Esto hace que sea necesario disponer de varias aplicaciones distintas, haciendo que la gestión de los equipos sea un proceso engorroso y tedioso.

Este proyecto surge de mi pasión por el deporte y como agradecimiento al club. La idea es proporcionar una solución web que centralice esos procesos.

Hoy en día existen ya soluciones diseñadas para gestionar equipos o clubes deportivos, aunque este proyecto se centra únicamente en la parte del equipo. Estas son algunas de esas soluciones:

\textbf{SportEasy}

SportEasy es una plataforma de origen francés creada en el año 2012. Permite el registro de equipos deportivos. Ofrece una gran variedad de funcionalidades para gestionarlos, y la cantidad de deportes disponibles también es muy amplia, incluido el hockey línea.

Esta solución facilita la gestión de los datos de los miembros del equipo, ya sean jugadores o padres. También ofrece un sistema de mensajería, un calendario para planificar los eventos deportivos y extra-deportivos y un sistema de convocatorias. Además, incluye una función para preparar la alineación antes de los partidos y una gestión de tareas para éstos. Por último, ofrece la planificación de las jornadas de la temporada, seguimiento de incidencias del partido y estadísticas de los jugadores y el equipo. Al finalizar el partido, SportEasy permite votar al mejor jugador del partido, así como puntuar la actuación del equipo y de cada jugador. \cite{sporteasy}

Es la aplicación que más se asemeja a este proyecto.

\textbf{Sportmember}

Sportmember es una solución danesa desarrollada para la gestión de clubes deportivos \cite{sportmember}. Entre todas sus funcionalidades, incluye varias destinadas a la gestión de los equipos deportivos del club:

\begin{itemize}
  \item Calendario para coordinar eventos
  \item Control de asistencia a eventos (partidos y entrenamientos entre otros)
  \item Comunicación por correo electrónico con jugadores
  \item Seguimiento de estadísticas de los deportistas
  \item Sanciones (multas internas del equipo)
  \item Creación de alineaciones y tácticas
  \item Informe del partido
\end{itemize}

\textbf{Clupik}

Clupik es una plataforma española orientada a la gestión de un club deportivo \cite{clupik}. Uno de sus módulos está dedicado a la gestión deportiva, y contiene las siguientes funcionalidades relacionadas con la gestión de los equipos del club:

\begin{enumerate}
  \item \textbf{Entrenamientos:} Dispone de un calendario para cada equipo o grupo de entrenamiento para planificar entrenamientos, actividades, eventos, etc. Permite programar las sesiones de los deportistas y controlar su asistencia. Puede generar informes para cada deportista y hacer un seguimiento y control de las lesiones. Incluye un módulo COVID para registrar las temperaturas de los deportistas y tener un control de los protocolos en el club.
  \item \textbf{Competiciones para clubes:} Permite visualizar todos los partidos y las clasificaciones de todos los equipos del club, enviar convocatorias digitalmente, registrar la asistencia de los jugadores y obtener estadísticas de los deportistas, y genera publicaciones automáticas con los resultados de los equipos del club. Aunque esta última función solo está disponible para algunos deportes.
\end{enumerate}

Además de estas funcionalidades, también incluye la gestión de los miembros del club mediante una única base de datos.

Esta aplicación cuenta con muchas más funcionalidades que las comentadas anteriormente, pero no forman parte de la gestión de los equipos del club.

En el caso de este proyecto, implementará una funcionalidad para gestionar pedidos de material para el equipo y permitirá la anotación de estadísticas, tanto de jugadores como del equipo, durante el partido. Además, proporcionará recomendaciones basándose en las estadísticas recopiladas durante el partido, para cada jugador y para el equipo.

\chapter{Objetivos y alcance}

\section{Objetivos}

El objetivo principal de este proyecto es diseñar y desarrollar una solución web que organizace y facilite los procesos de gestión de un equipo deportivo, a la vez que proporciona herramientas para mejorar su rendimiento. Cabe destacar que este proyecto ha sido diseñado para uno de los equipos de un club en específico. Para lograr el objetivo principal del proyecto, se han establecido varios objetivos basándose en el principal. Estos objetivos servirán para comprobar si el resultado final del proyecto es un éxito o un fracaso. Dichos objetivos son los siguientes:

\begin{itemize}
  \item Objetivo 1: Diseñar y desarrollar una aplicación web que centralice los procesos de gestión más importantes y repetitivos del equipo deportivo.
  \item Objetivo 2: Implementar un sistema de login que permita el acceso únicamente a integrantes del club.
  \item Objetivo 3: Implementar un sistema de seguimiento de incidencias y estadísticas de los partidos en directo.
  \item Objetivo 4: Desarrollar un módulo inteligente que ofrezca recomendaciones sobre aspectos del partido a mejorar.
  \item Objetivo 5: Implementar distintos tipos de roles para el acceso a la aplicación web.
  \item Objetivo 6: Diseñar una interfaz original y personalizada para el club deportivo de referencia.
  \item Objetivo 7: Desarrollar una aplicación web adaptable a cualquier tipo de pantalla y dispositivo.
\end{itemize}

\section{Alcance}

Dado el carácter académico de este trabajo, el proyecto ha sido desarrollado con recursos y tiempo limitados. Esto implica que su alcance ha tenido que determinarse con claridad desde el principio. Además, se planea la ampliación del proyecto una vez realizada su defensa, por lo que delimitar sus funcionalidades para la presentación en la universidad ha sido una parte importante. Los objetivos anteriormente mencionados forman parte del alcance. Además se enumeran a continuación aspectos que también entran en el mismo:

\begin{enumerate}
  \item Desarrollo de la base de datos.
  \item Implementación de un sistema de login social.
  \item Desarrollo de la API REST.
  \item Implementación de un modelo de inteligencia artificial generativa comercial.
  \item Uso de Docker para el despliegue de la solución.
\end{enumerate}

Para la realización de este proyecto, también ha sido fundamental tener claro qué no forma parte del alcance de éste:

\begin{enumerate}
  \item Desarrollo de un sistema de seguimiento de jugadores y disco en tiempo real.
  \item Implementación de diferentes equipos del club.
  \item Desarrollo y entrenamiento de un modelo de inteligencia artificial propio.
  \item Almacenamiento de datos por temporadas.
  \item Persistencia de incidencias de partidos.
  \item Seguimiento de estadísticas por cada liga.
\end{enumerate}

\chapter{Metodología}

\section{Metodologías iterativas e incrementales}

Las metodologías iterativas son metodologías que dividen los proyectos en ciclos repetitivos cortos. A muchas de ellas también se les llama incrementales, ya que en cada ciclo iterativo añaden nuevas funcionalidades o módulos al producto hasta completarlo.

\begin{itemize}
  \item \textbf{Flexibilidad:} Este tipo de metodologías aportan mucha flexibilidad, ya que permiten cambiar los requisitos rápidamente si las necesidades del cliente sufrieran algún cambio.
  \item \textbf{Reducción de riesgos:} Gracias a dividir el proyecto en ciclos cortos, los errores se detectan y corrigen rápidamente. De esta forma, se evitan grandes problemas que se puedan acumular a lo largo del proyecto.
  \item \textbf{Feedback continuo:} Debido al caracter incremental de estas metodologías, es posible probar y enseñar el producto al cliente cada vez que se añade una nueva funcionalidad. De esta manera, se obtiene feedback del cliente después de implementar cada funcionalidad y adaptar a su gusto lo que fuera necesario.
\end{itemize}

En este proyecto he decidido utilizar este tipo de metodología en la fase de realización del proyecto para ir implementando las funcionalidades poco a poco y corregir rápidamente cualquier error que pudiera producirse.

Decidí decantarme por utilizar esta metodología en la fase de realización del proyecto porque me parecía una metodología razonable y adaptable a mis circunstancias, ya que me permitía trabajar de forma autónoma y probar el resultado cada vez que implementaba una nueva funcionalidad. Además, creo que es una metodología que encajaba perfectamente con la planificación elaborada para esa fase del proyecto.

\section{Especificación del diseño}

Para llevar a cabo el proyecto, ha sido necesario especificar el diseño del mismo antes de empezar con su desarrollo. Dicho diseño ha sido especificado en base a los requisitos funcionales y no funcionales y los objetivos del proyecto. El propósito de este apartado es definir el diseño de la arquitectura de la solución, el diseño relacional de la base de datos y el diseño de la interfaz de la aplicación web.

\begin{enumerate}
  \item \textbf{Backend:} Está desarrollado en Java 21, haciendo uso del framework SpringBoot. La parte backend se encarga de comunicarse con la base de datos mediante una API REST, desarrollada con las herramientas que proporciona SpringBoot para ello. Almacena datos y los recupera cuando es necesario, y los envía a la parte frontend para que se ella la que se encargue de mostrar la información al usuario.
  \item \textbf{Frontend:} El frontend es quien se encarga de recibir los datos que llegan de la parte backend para mostrarlos al usuario en pantalla. Está desarrollado en con React.
  \item \textbf{Base de datos relacional:} El backend se comunica con ella para almacenar y recuperar los datos que sean necesarios cuando sea necesario. Funciona como almacenamiento persistente del proyecto, y se ha hecho uso de MySQL para su gestión.
  \item \textbf{Anthropic:} Es una organización que dispone de modelos de inteligencia artificial generativa. La parte frontend llama a la API REST del proyecto para que sea el backend quien se comunique con uno de los modelos de IA de Anthropic. El backend recibirá la respuesta del modelo y la enviará al frontend para mostrarla al usuario.
  \item \textbf{Docker:} Es una herramienta de contenerización que permite empaquetar una aplicación y sus dependencias en un contenedor. Se utilizará para empaquetar la aplicación en un contenedor y poder ejecutarla en cualquier entorno.
\end{enumerate}

La parte backend hace uso de una base de datos relacional para almacenar toda la información del proyecto. Además, el backend se comunicará con Anthropic para utilizar uno de sus modelos de IA. El proyecto estará embebido dentro de un contenedor de Docker.
